# Kindred 2.6.0

2.5 added email. 2.6 uses it to make signing in simpler, and makes the sign-in with Google or a personal Microsoft account
something an operator can set up in minutes. Try Kindred on two invented families first:
[kindred-demo.niklas-heer.workers.dev](https://kindred-demo.niklas-heer.workers.dev).

## For everyone

- **A sign-in code by email**, where your server offers it. Choose *Email me a sign-in code* on the sign-in page and type
  your account's address; a six-digit code arrives, and works once, for 10 minutes, in the browser that asked. It is a way
  back in, for example after losing every device. If your account has two-step codes, they are still asked. You get a security
  notice after each sign-in this way.
- **A new passkey straight away.** After signing in with a code you can add a passkey on the new device without more proof.

## For operators

- **Code by email** is off by default: switch on the *Code by email* card in the console's Sign-in tab. It stays unavailable
  until your server sends email (Email tab, which needs `KINDRED_ORIGIN`). Codes go only to an account's **confirmed** address,
  at most 3 an hour per account. An operator signed in with a code needs two-step codes to open the console, and a code is never
  an operator's proof. **The trade-off:** whoever can read a member's mail can get in, unless the account has a password with
  two-step codes (a member needs a password before turning them on).
- **Guided single sign-on setup** in the Sign-in tab: *Add a provider*, then pick Google or a personal Microsoft account
  (Outlook.com, Hotmail, Xbox). The wizard gives the exact redirect URL and every value to paste, and links to the right page
  of the provider's console. **Test sign-in** runs the real sign-in with your own account and creates nothing; once it works,
  you turn the provider on for your relatives (with the Single sign-on card on). Apple is not included.
- **Health warnings**: Google deletes OAuth clients nobody used for six months, and Microsoft client secrets expire. The
  console warns you before either happens, and the audit records whether a saved provider had been tested.

## Upgrading

Back up first. Accounts migrations 0058 and 0059 are new and keep all stored data; 0059 makes the short-lived
`oidc_flow` table again, so a single sign-on sign-in in progress during the upgrade has to start over. On Node they apply at
start, on Cloudflare `mise run deploy` applies them before the new Worker goes live.

- Nothing to do: the code by email is off and no provider changes until you act, and there are no new settings.
- To turn the code on, set up email first, then see
  [A sign-in code by email](../self-host.md#a-sign-in-code-by-email). To set up Google or Microsoft, see
  [Single sign-on](../self-host.md#single-sign-on-openid-connect).
- The hosting guides now describe what Kindred emails; they no longer say it sends none.
